Iranian Payment Gateway — Without a Database

سرویس مستقل پرداخت با پشتیبانی از زیبال، زرین‌پال و سپ. نتایج از طریق وب‌هوک به اپلیکیشن شما ارسال می‌شود.

Standalone payment service supporting Zibal, Zarinpal, and SEP. Results delivered to your app via webhooks.

Introduction

با این سرویس آشنا شوید — چه کاری انجام می‌دهد و جریان پرداخت چگونه است.

Learn what this service does and how the payment flow works.

ir-payment-gateway یک میکروسرویس مستقل است که بین اپلیکیشن شما و درگاه‌های بانکی ایران قرار می‌گیرد — بدون نیاز به دیتابیس.

ir-payment-gateway is a standalone microservice between your app and Iranian payment gateways — no database required.

Declare your server's static IP. Requests from other IPs are rejected. Server move = new IP request.

نحوه دریافت سرویس استرداد وجه (SEP)

Getting SEP Refund Service

راهنمای فعال‌سازی قابلیت بازگشت وجه در درگاه سپ — فرآیندی مجزا از دریافت درگاه پرداخت.

Guide to enabling SEP refund capability — a process separate from getting the payment gateway.

SEP_USERNAME · SEP_PASSWORD

فرآیند مجزا: ریفاند در سپ یک فرآیند بانکی زمان‌بر است که مستقیماً توسط بانک فعال می‌شود — قرارداد جدید لازم نیست، اما مراحل اداری و فنی زیر الزامی است.

Separate process: SEP refunds are a time-consuming banking process activated directly by the bank — no new contract, but the steps below are required.

مراحل راه‌اندازی بانکی
Banking Setup Steps

۱ — کف موجودی بانک

1 — Minimum Balance

بانک مبلغ مشخصی (مثلاً ۳۰۰ میلیون تومان) را به عنوان شرط صدور اعلام می‌کند — باید تا زمان صدور کارت موجود باشد.

Bank requires a minimum balance (e.g. 3B Rials) until virtual card issuance.

۲ — صدور کارت مجازی

2 — Virtual Card Issuance

درخواست از طریق سپ به بانک ارجاع می‌شود — فرآیند بین‌بانکی و زمان‌بر

SEP refers request to bank — interbank process, takes time

۳ — شارژ تنخواه ریفاند

3 — Refund Float Balance

کارت مجازی را همیشه شارژ نگه دارید — بدون موجودی، API ریفاند خطا می‌دهد

Keep virtual card funded — insufficient balance causes API errors

۴ — IP مجزا برای ریفاند ⚠️

4 — Separate Refund IP ⚠️

IP سرور ریفاند جدا از IP درگاه اصلی whitelist می‌شود — امنیت بالاتر

Refund server IP whitelisted separately from payment gateway IP

۵ — دریافت کلیدهای API

5 — API Credentials

پس از اتمام فرآیند بانکی، نام کاربری و رمز وب‌سرویس ریفاند ایمیل می‌شود → SEP_USERNAME و SEP_PASSWORD

After banking process, refund API credentials emailed → SEP_USERNAME & SEP_PASSWORD

نحوه کار API
How the API Works

بدون شماره کارت

No Card Number Needed

فقط RefNum تراکنش اصلی + مبلغ — بانک به کارت خریدار برمی‌گرداند

Only original RefNum + amount — bank returns to buyer's card

محدودیت زمانی

Time Limit

ممکن است محدودیت روز/هفته پس از تراکنش اصلی وجود داشته باشد

May have day/week limit after original transaction

شرط: ریفاند فقط روی تراکنش‌های موفق با تسویه کامل و شناسه معتبر امکان‌پذیر است. ابتدا باید درگاه سپ را فعال کرده باشید.

Condition: Refund only works on successful, fully settled transactions. You must have an active SEP gateway first.

Example Express.js handler:

javascript
app.post('/payments/success', async (req, res) => {
  const secret = req.headers['x-webhook-secret'];
  if (secret !== process.env.WEBHOOK_SECRET)
    return res.status(401).json({ error: 'Unauthorized' });

  const { orderId, code, status } = req.body;
  if (status === 'success') {
    await db.orders.update({ id: orderId },
      { status: 'paid', refCode: code });
  }
  res.json({ ok: true }); // always respond with 200
});

⚠️ محدودیت‌های زرین‌پال Production

⚠️ Zarinpal Production Limitations

  • دامنه callback: زرین‌پال production فقط callback URL هایی را می‌پذیرد که دامنه‌شان با دامنه ثبت‌شده در پنل مطابقت دارد. localhost قابل استفاده نیست.
  • Callback domain: Zarinpal production only accepts callback URLs whose domain matches the domain registered in your Zarinpal panel. localhost will be rejected with error code -14.
  • HTTP 401: اگر خطای 401 دریافت کردید، ممکن است به دلیل Merchant ID نامعتبر، IP مسدودشده، یا عدم تطابق دامنه callback باشد.
  • HTTP 401: A 401 response can indicate an invalid Merchant ID, a blocked IP, or a callback domain mismatch.
  • تست لوکال: برای توسعه محلی، همیشه از gateway: "zarinpal_sandbox" استفاده کنید.
  • Local testing: Always use gateway: "zarinpal_sandbox" for local development — sandbox has no domain restriction.

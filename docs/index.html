سرویس مستقل پرداخت با پشتیبانی از زیبال، زرین‌پال و سپ. نتایج از طریق وب‌هوک به اپلیکیشن شما ارسال می‌شود.

Standalone payment service supporting Zibal, Zarinpal, and SEP. Results delivered to your app via webhooks.

Introduction

با این سرویس آشنا شوید — چه کاری انجام می‌دهد و جریان پرداخت چگونه است.

Learn what this service does and how the payment flow works.

ir-payment-gateway یک میکروسرویس مستقل است که بین اپلیکیشن شما و درگاه‌های بانکی ایران قرار می‌گیرد — بدون نیاز به دیتابیس.

ir-payment-gateway is a standalone microservice between your app and Iranian payment gateways — no database required.

Getting SEP Refund Service

راهنمای فعال‌سازی قابلیت بازگشت وجه در درگاه سپ — فرآیندی مجزا از دریافت درگاه پرداخت.

Guide to enabling SEP refund capability — a process separate from getting the payment gateway.

SEP_USERNAME · SEP_PASSWORD

فرآیند مجزا: ریفاند در سپ یک فرآیند بانکی زمان‌بر است که مستقیماً توسط بانک فعال می‌شود — قرارداد جدید لازم نیست، اما مراحل اداری و فنی زیر الزامی است.

Separate process: SEP refunds are a time-consuming banking process activated directly by the bank — no new contract, but the steps below are required.

تست درگاه بدون پرداخت واقعی

Test Gateway Without Real Payment

اگر می‌خواهید جریان پرداخت را قبل از go-live امتحان کنید — بدون اینکه مبلغی از حساب کسر شود — این راهنما را دنبال کنید. فقط زرین‌پال سندباکس دارد.

If you want to try the payment flow before going live — without charging real money — follow this guide. Only Zarinpal provides a sandbox.

فقط زرین‌پال: در میان درگاه‌های پشتیبانی‌شده این پروژه (زیبال، زرین‌پال، سپ)، فقط زرین‌پال محیط سندباکس رسمی دارد. زیبال و سپ سندباکس عمومی مشابه ندارند — برای تست یکپارچه‌سازی از zarinpal_sandbox استفاده کنید.

Zarinpal only: Among the gateways supported by this project (Zibal, Zarinpal, SEP), only Zarinpal provides an official sandbox. Zibal and SEP have no equivalent public sandbox — use zarinpal_sandbox for integration testing.

سندباکس چیست؟
What is the Sandbox?

سندباکس زرین‌پال یک محیط تست جداگانه است که API و صفحه پرداخت واقعی را شبیه‌سازی می‌کند، اما هیچ پول واقعی از حساب کاربر کسر نمی‌شود. جریان کامل — درخواست پرداخت، redirect، verify و وب‌هوک — دقیقاً مثل production اجرا می‌شود.

The Zarinpal sandbox is a separate test environment that mirrors the real API and payment page, but no real money is charged. The full flow — payment request, redirect, verify, and webhook — runs exactly like production.

مراحل فعال‌سازی
Activation Steps

۱ — تنظیم Merchant ID

1 — Set Merchant ID

در فایل .env مقدار ZARINPAL_MERCHANT را قرار دهید. برای شروع می‌توانید از هر UUID معتبر ۳۶ کاراکتری استفاده کنید — سندباکس مرچنت production را هم می‌پذیرد. جزئیات دریافت مرچنت واقعی در بخش درگاه زرین‌پال.

Set ZARINPAL_MERCHANT in your .env. To get started you can use any valid 36-char UUID — sandbox accepts production merchant IDs too. See Zarinpal gateway guide for obtaining a real merchant ID.

۲ — انتخاب روش فعال‌سازی

2 — Choose Activation Method

دو روش دارید: per-request (توصیه‌شده) با gateway: "zarinpal_sandbox" در هر درخواست، یا سراسری با ZARINPAL_SANDBOX=true در env که همه کال‌های zarinpal را به سندباکس هدایت می‌کند.

Two options: per-request (recommended) with gateway: "zarinpal_sandbox" on each payment, or global with ZARINPAL_SANDBOX=true in env to redirect all zarinpal calls to sandbox.

۳ — ارسال درخواست پرداخت تست

3 — Send a Test Payment

سرویس را اجرا کنید و یک POST به /api/payments بزنید. کاربر به صفحه پرداخت سندباکس (sandbox.zarinpal.com) هدایت می‌شود.

Run the service and POST to /api/payments. The user is redirected to the sandbox payment page (sandbox.zarinpal.com).

json
{ "orderId": "test-001", "amount": 10000, "gateway": "zarinpal_sandbox" }

۴ — تأیید وب‌هوک

4 — Verify Webhook

پس از پرداخت تست، سرویس verify را انجام می‌دهد و POST به PAYMENT_SUCCESS_WEBHOOK_URL می‌زند — payload دقیقاً مثل production است. handler وب‌هوک خود را قبل از go-live تست کنید.

After the test payment, the service verifies and POSTs to PAYMENT_SUCCESS_WEBHOOK_URL — payload is identical to production. Test your webhook handler before going live.

دو روش فعال‌سازی
Two Activation Methods

روش ۱ — per-request توصیه‌شده

Option A — per-request Recommended

در هر درخواست پرداخت، gateway را مشخص کنید:

Specify the gateway on each payment request:

json
{ "gateway": "zarinpal_sandbox" }
  • production و sandbox همزمان قابل استفاده‌اند
  • برای توسعه لوکال ایده‌آل است
  • نیازی به تغییر env نیست
  • Production and sandbox can run side by side
  • Ideal for local development
  • No env changes needed

روش ۲ — سوئیچ سراسری

Option B — Global Switch

همه درخواست‌های zarinpal را به سندباکس هدایت می‌کند:

Redirects all zarinpal requests to sandbox:

Handler نمونه در Express.js:

Example Express.js handler:

javascript
app.post('/payments/success', async (req, res) => {
  const secret = req.headers['x-webhook-secret'];
  if (secret !== process.env.WEBHOOK_SECRET)
    return res.status(401).json({ error: 'Unauthorized' });

  const { orderId, code, status } = req.body;
  if (status === 'success') {
    await db.orders.update({ id: orderId },
      { status: 'paid', refCode: code });
  }
  res.json({ ok: true }); // always respond with 200
});

مهم: اگر endpoint شما کد غیر 200 برگرداند، وب‌هوک به صف retry اضافه شده و با backoff نمایی مجدداً ارسال می‌شود.

Important: Non-200 response adds the webhook to the retry queue with exponential back-off.
